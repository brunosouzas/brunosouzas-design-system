# Identity v2: guide and system (AB#268, phase 5 of AB#263)

## Problem

Phases 1-4 of the visual identity rework (Wheeler's method; epic AB#263) are closed and approved by the owner: the research (AB#264), the strategy (AB#265, decisions E1-E12), the identity studio (AB#266, decisions I1-I13: the Mira protagonist, the cast Visor/Drone/Kiu/Sinal, the three-layer colour table with measured AA, the EIP/delivery/AI notation, the signature device) and the application prototype (AB#267, decisions A1-A9: covers per track, the real Content-Based Router diagram, LinkedIn/og/favicon/avatar, home and article, the stackledger sample, the motion storyboard). All of it lives in Penpot and in scratch Python renders; none of it is in the published package yet. `docs/adr/0003` (colour) and `0005` (cast) and every piece in `src/pieces/` still describe the identity that phase 3 replaced: a flat token list with no primitive/semantic/component layers, a 21-entry literal colour bank per cover, and a seven-role engineering cast (Dev, AI agent, Architect, DevOps, Data, Requester, Message) with no brand characters.

This change carries the approved identity into the design system's code, tokens and release, so the package, the published covers and the kit rules describe one real source instead of an exploration file.

## What changes

- **Two new ADRs**, replacing 0003 and 0005 in full (they are not amended: the owner decided the whole colour and cast systems are redesigned, "mudar o que for necessário para seguir o novo padrão").
  - **ADR 0006 (colour and tokens):** the three-layer architecture (primitive → semantic → component), the new brand/site semantic roles (`bg`, `surface`, `text`, `text-muted`, `border`, `border-strong`, `accent`, `accent-text`, `on-accent`, `success`, `failure`, `warning`, the three track colours) with the AA ratios measured in phase 3, light and dark. The existing diagram-state colours (healthy, blocked, transitional, caller, backend, failure, failFast — used in 28 published diagrams and the approved motion pilots) move into the same three-layer shape as semantic tokens of their own domain (`state.*`), keeping their current values and meaning: nothing published breaks, but the architecture is now one, not two.
  - **ADR 0007 (cast):** the new cast (Mira the protagonist; Visor, Drone, Kiu, Sinal as the four pillar/product roles) replaces the engineering-role cast for every future use. Existing roles are re-mapped onto the nearest new or kept character where the story still reads (decided per character in `design.md`), and a new supporting role is added, with its own sheet, when no existing character tells that part of the story without ambiguity — never a silent reuse that would misread. Videos stay one file for both languages (ADR 0005, unchanged); only sequence/body diagrams render one SVG per language.
- **Tokens restructured** in `tokens/source.json` into the three layers, generated the same way (`npm run tokens`).
- **New pieces**: `mira` (the protagonist, front/back, four state faces, light/dark), the four role characters (as `mascot`-style pieces or a parallel `cast` entry, decided in `design.md`), six bank objects (Correio, Lume, Carga, Anel, Módulo, Hub, screen-off), the 19-icon notation (13 EIP + 3 delivery + 3 AI) as a **brand notation family**, separate from and alongside the existing 26 diagram EIP icons (`eip-icons.ts`), which keep drawing patterns inside body diagrams unchanged. The notation's EIP icons redraw each pattern's market-recognised silhouette (the shape a reader who knows EIP already associates with that pattern) in the new ink-outline/flat grammar — never a copy of Hohpe's book artwork, but not an arbitrary new glyph either.
- **Cover/banner/diagram/icon commands** gain: cover backgrounds keyed by content track (`track.integration`, `track.delivery`, `track.ai`) instead of the 21-entry literal bank, the Mira+symbol signature lockup, new favicon/avatar/LinkedIn-card formats sized per A3-A5. Existing per-article cover metaphors (COV-1/2) are kept; only the background role, the type and the signature change.
- **Release** `@brunosouzas/design-system@0.6.0` (minor; the package is still 0.x, consumed only by `brunosouzas.com` and `stackledger`, no deprecation shims for the retired cast/token names).
- **Consumers**: the `illustration` kit skill's pinned version bumps to 0.6.0 (own PR); the 21 published covers are rebuilt from their existing specs against 0.6.0 (own PR in `brunosouzas-content`, precedent AB#140); `brunosouzas.com` and `stackledger` get version-bump follow-up PRs (S8).
- **Kit rules**: `illustration` (COV-4 replaced by track-based grouping; the EIP notation split from diagram icons made explicit), `motion` (CAST rules point at the new cast; a rule on when a technical scene may reuse a brand character vs needs a new one), `art-direction` (STU-2 removed: the studio's Penpot files are no longer the only record — the shipped pieces now have a real source in this package).

## Out of scope

- Rebuilding the 14 published body diagrams or any scene/video (not asked by AB#268; diagrams and scenes keep today's diagram-state colours and the existing 26 EIP icons).
- The "Ferramentas pessoais" category icon's final glyph choice (triage TRI-1, the owner's call stays with the agent, not reopened here as a question, but the icon itself is built as a requested piece).
- Any further LinkedIn/post distribution work (`publishing` phase 2, not open yet).
- Opening a figma-vs-penpot spike: Penpot was used through phases 3 and 4 and stays the studio's exploration tool; this change does not touch `art-direction`'s STU-1 or the exploration process, only removes the now-resolved STU-2.
